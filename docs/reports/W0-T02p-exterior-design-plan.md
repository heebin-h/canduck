## 0. 목표와 완료 기준

**목표**: heebin이 만든 속이 꽉 찬 캐릭터 외형(머리·팔·다리 일체)을 받아 다음을 완성한다.
- 셸 + 골격 + 부품 마운트
- P1S 출력용 파츠 세트
- 10-DOF 실보행 사양(W0-T02o) 반영

**완료 기준 (전부 충족해야 완료)**:
1. 모든 부품(§2 목록)이 간섭 없이 들어가고, 관절 10개가 각각 요구 가동범위(§5 P5) 안에서 외피와 충돌하지 않는다. CAD 검증 리포트로 확인한다.
2. 출력 파츠 전부 watertight이고, Bambu Studio 슬라이싱에서 에러가 없다.
3. P1S로 출력한 뒤 가조립을 해서, 실측으로 수정한 v1에서 서보·PCB·배터리가 공구 없이 끼워지거나 지정 나사만으로 고정된다.

## 3. 파일 구조 (예정)

```
/Users/heebiny/canduck/hardware/cad/
├── pyproject.toml            # Python 3.12 venv (cadquery, trimesh, manifold3d)
├── params/parts.yaml         # 부품 치수 DB: 값·출처URL·실측값·공차 (하드코딩 금지)
├── params/print.yaml         # 재료별 공차·벽두께·insert 홀 지름 (P2 결과)
├── src/                      # 생성 스크립트 (골격·마운트·결합·검증)
└── reports/                  # 공간검증·가동범위·슬라이싱 리포트 (렌더 PNG 포함)
/Users/heebiny/canduck/hardware/models/
├── raw/                      # heebin 입력: canduck-body-v{n}.stl
└── out/                      # 생성물 STL/STEP — .gitignore (코드로 재생성)
```

- raw는 커밋한다. 파일당 수십 MB를 넘으면 git LFS를 검토한다.
- out을 커밋하지 않는 이유: 재생성이 가능하고, 바이너리 diff가 무의미하다.

## 7. 진행 순서 요약

```
P0 환경 ─┬─ P1 부품DB ── P2 쿠폰(출력·실측)
         └─ P3 블록아웃(heebin) ── P4 공간검증 ─(실패 시 P3 수정)
                                      └─ P5 분할선 제안 → 승인
                                           └─ P3' 디테일(heebin) ── P4 재검증
                                                └─ P6 셸화 ── P7 골격 ── P8 결합·출력준비
                                                                          └─ P9 출력·실측 → v1
```

P0~P2는 외형과 무관하므로 heebin의 블록아웃 작업과 **병행**한다.
